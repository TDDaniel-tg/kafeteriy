## 1. Описание системы

**«Кафетерий льгот»** — это высоконагруженная корпоративная веб-платформа для управления материальными и нематериальными поощрениями сотрудников компании. Платформа решает задачи персонализации соцпакета, автоматизации выдачи страховых полисов ДМС, распределения корпоративных баллов, закупки электронных сертификатов и бесшовной интеграции с финансовым и кадровым контуром предприятия (1С:ЗУП, 1С:Бухгалтерия, SSO).

### Ключевые возможности:
1. **Персональный онбординг (ФТ-ОНБ)**: интерактивный тур, анкетирование интересов, персональная витрина рекомендаций.
2. **Балансы и FIFO-списание (ФТ-БАЛ)**: разделение сгорающих (`burnable`) и несгорающих баллов. Автоматическое списание в первую очередь баллов с ближайшим сроком сгорания.
3. **Двойная бухгалтерская запись (Ledger)**: строгий аудит всех движений баллов, запрет отрицательного баланса, идемпотентность финансовых транзакций.
4. **Конструктор ДМС (ФТ-ДМС)**: выбор уровней страхования (Стандарт, Комфорт, VIP), опции франшизы (0%, 10%, 20%), прикрепление членов семьи с софинансированием.
5. **Кампании «Окна выбора» (ФТ-ОКН)**: периодические окна фиксации долгосрочных пакетов с обратным отсчетом времени и механизмом автоназначения (Fallback).
6. **Каталог и сертификаты (ФТ-КАТ, ФТ-СЕР, ФТ-ЗАК)**: мультикатегорийный каталог, штрихкоды и промокоды (Giftery, Простодар, ритейл), запрет отмены выданных кодов (ФТ-ЗАК.6).
7. **Социальные механики и геймификация (ФТ-СОЦ, ФТ-ГЕЙ)**: P2P-переводы баллов коллегам с удержанием 25% сервисного сбора, бейджи достижений, пожертвования в благотворительные фонды (0% комиссия).
8. **Административный центр «Пульт» (АДМ-01 — АДМ-24)**: 24 специализированных экрана управления сотрудниками, бюджетами, каталогом, ДМС-реестрами, тикетами поддержки со строгим SLA, коммуникациями и финансовыми отчетами с расчетом НДС.
9. **Неизменяемый аудит-лог (AuditLog SHA-256)**: криптографическая хеш-цепочка, блокировка любых изменений и удалений исторических записей.
10. **Раздел 15 ТЗ (Копирайт)**: обязательный компонент `<DeveloperCredit />` («Разработано TDDaniel» со ссылкой на `https://tddaniel.netlify.app`) интегрирован во все пользовательские и административные экраны.

## 2. Архитектура проекта

Система построена по архитектуре **Modular Monolith** с разделением зон ответственности:

```
├── backend/
│   ├── core/                        # Ядро Django (settings, urls, celery, asgi/wsgi)
│   ├── apps/
│   │   ├── accounts/                # Пользователи, профили, онбординг, сессии
│   │   ├── rbac/                    # Ролевая модель (Сотрудник, Декрет, VIP, HR, Админ)
│   │   ├── points/                  # Баллы, субсчета, FIFO-списание, Главная книга (Ledger)
│   │   ├── budgets/                 # Бюджетирование подразделений и лимиты
│   │   ├── campaigns/               # Окна выбора, таймеры, автоназначение (Fallback)
│   │   ├── catalog/                 # Категории, льготы, квоты, софинансирование
│   │   ├── orders/                  # Корзина, заказы, правила отмены (ФТ-ЗАК.6)
│   │   ├── vouchers/                # Генератор промокодов, штрихкоды EAN/Code-128
│   │   ├── health_dms/              # Программы ДМС, франшизы, родственники
│   │   ├── social/                  # P2P-переводы (25% сбор), благотворительность
│   │   ├── comms/                   # Центр коммуникаций, email-шаблоны, пуш
│   │   ├── surveys_gamification/    # Опросы вовлеченности (eNPS), ачивки и бейджи
│   │   ├── support/                 # Служба заботы, тикеты, контроль SLA
│   │   ├── settings_platform/       # Системные настройки (курс балла, лимиты)
│   │   ├── audit/                   # Неизменяемый крипто-аудит (SHA-256)
│   │   ├── integrations/            # Шлюзы 1C:ЗУП, Giftery, Prostodar, SSO
│   │   └── api/                     # Единый REST API роутер и OpenAPI схема
│   └── tests/                       # Автоматические тесты pytest
├── frontend/
│   ├── src/
│   │   ├── DeveloperCredit.tsx      # Компонент копирайта разработчика TDDaniel
│   │   ├── App.tsx                  # Главный компонент, роутинг экранов, футеры
│   │   ├── ui.tsx                   # Токенизированные компоненты дизайна Figma
│   │   ├── index.css                # Дизайн-токены, Tailwind CSS v4, темы
│   │   └── components/
│   │       ├── AdminPanel.tsx       # Административные экраны АДМ-01..14, 16..17, 23
│   │       ├── AdminWindows.tsx     # Экран АДМ-18 (Окна выбора и кампании)
│   │       ├── AdminComms.tsx       # Экран АДМ-19 (Коммуникации и рассылки)
│   │       ├── AdminSurveys.tsx     # Экран АДМ-20 (Опросы вовлеченности и eNPS)
│   │       ├── AdminIntegrations.tsx# Экран АДМ-21 (Шлюзы и интеграции)
│   │       ├── AdminReports.tsx     # Экран АДМ-22 (Бухгалтерские отчеты и НДС)

│   │       └── AdminAudit.tsx       # Экран АДМ-24 (Неизменяемый крипто-аудит)
├── deploy/                          # Kubernetes манифесты (Deployment, Ingress, etc.)
├── docs/                            # Полный комплект документации
│   ├── ADMIN_GUIDE.md               # Руководство администратора (АДМ-01 — АДМ-24)
```

## 3. Быстрый старт

### Вариант А: Запуск в Docker Compose (Рекомендуемый)

1. Клонируйте репозиторий и создайте файл окружения:
   ```bash
   cp .env.example .env
   ```
2. Запустите все сервисы платформы (Бэкенд, Фронтенд, PostgreSQL, Redis, Celery Worker, Celery Beat):
   ```bash
   docker compose up --build -d
   ```
3. Заполните базу данных реалистичными демонстрационными данными:
   ```bash
   docker compose exec backend python manage.py seed_demo_data
   ```
4. Откройте в браузере:
   * **Портал сотрудника и Админ-панель**: `http://localhost:5173/` (или `http://localhost:80/`)
   * **OpenAPI / Swagger документация**: `http://localhost:8000/api/docs/`
   * **Django Admin**: `http://localhost:8000/admin/`

---

### Вариант Б: Локальный запуск для разработки

#### 1. Запуск Backend:
```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo_data
python manage.py runserver 0.0.0.0:8000
```

#### 2. Запуск Frontend:
```bash
cd frontend
npm install
npm run dev
```

## 5. Тестирование и верификация

### Запуск модульных и интеграционных тестов Backend:
```bash
backend/venv/bin/pytest
```
Тесты проверяют:
- Списание баллов строго по алгоритму **FIFO** (сначала сгорающие по дате, затем несгораемые).
- Двойную бухгалтерскую запись и идемпотентность проводок.
- Защиту от отмены для электронных сертификатов (ФТ-ЗАК.6).
- Неизменяемость лога `AuditLog` и валидность SHA-256 хеш-цепочки.
- Ролевые ограничения (РОЛ.1 — РОЛ.5) и экраны исключения.
- Расчет комиссии 25% при P2P-переводах.

### Запуск E2E-теста на соответствие копирайта (Раздел 15):
```bash
backend/venv/bin/pytest backend/tests/test_e2e_developer_credit.py
```
Тест запускает Playwright Chromium, открывает все ключевые маршруты и гарантирует наличие ссылки `https://tddaniel.netlify.app` с текстом `Разработано TDDaniel`.

### Сборка продакшн-бандла Frontend:
```bash
cd frontend && npm run build
```

## 6. Резервное копирование и Восстановление

В папке `scripts/` подготовлены shell-скрипты корпоративного уровня:
* **Создание бекапа**:
  ```bash
  ./scripts/backup_db.sh
  ```
  Создает сжатый дамп базы данных с контрольной суммой SHA-256 и ротацией 30 дней в папке `/backups`.
* **Восстановление из бекапа**:
  ```bash
  ./scripts/restore_db.sh /backups/cafeteria_backup_YYYYMMDD_HHMMSS.sql.gz
  ```
